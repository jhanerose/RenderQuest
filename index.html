Evaluation Log & Answer Key
13. In vs Uniform: An in variable receives unique, per-vertex data directly from the VBO. A uniform variable receives global data from the CPU that remains exactly the same for all vertices processed during that draw call.
14. Magnitude & Unit Vector: Formula: |v| = √(vx² + vy² + vz²). To create a unit vector, divide the original vector by its magnitude.
15. Fragment Shader: Decides the final color of the pixel that the fragment covers, applying colors, lighting, and textures.
16. Shader Program: A compiled and linked group of shaders. Steps: glCreateShader, glShaderSource, glCompileShader, glCreateProgram, glAttachShader, glLinkProgram.
17. Depth Test: Decides whether a fragment should be drawn based on distance from the camera (Z-buffer), ensuring closer objects hide objects further away.
18. Dot Product (Angle): v1 · v2 = |v1| × |v2| × cos(θ)
19. glBufferData: Uploads the array of vertex data from system RAM (CPU) into actual graphics memory (GPU).
20. Z-value of 0.0f: In a basic 2D drawing, depth is irrelevant. Because it faces the camera perfectly flat, z = 0.0.
21. EBO: Element Buffer Objects store indices that tell OpenGL which vertices to draw. It saves memory by allowing overlapping vertices to be defined only once and reused via their index.
22. Double Buffering: Rendering to a hidden "back" buffer while the screen displays the "front" buffer, swapping them when complete. It prevents visible screen tearing and flickering.
23. View Matrix: It shifts the entire world's coordinates to be relative to the camera's position and orientation, simulating a camera looking at the scene.
24. Projection matrices: Perspective causes foreshortening (distant objects appear smaller to mimic the human eye). Orthographic maintains parallel lines and exact sizes regardless of distance.
25. Texture Atlas: A single large image containing many smaller sprites. It drastically reduces expensive state changes (texture bindings) during rendering.
26. Mipmaps: Pre-calculated, lower-resolution versions of a texture. They solve aliasing (shimmering) on distant objects and improve GPU cache performance.
27. Filtering: GL_NEAREST selects the exact closest pixel, resulting in a blocky/pixel-art look. GL_LINEAR interpolates between neighboring pixels for a smooth, blurry look.
28. Backface Culling: Discarding polygons facing away from the viewer to save rendering time. It determines "facing" by the winding order (clockwise vs counter-clockwise) of the vertices.
29. Framebuffer Object (FBO): An off-screen rendering destination. Common uses include post-processing effects, shadow mapping, or rendering mirrors.
30. Alpha Blending: Result Color = (Source Color * Source Alpha) + (Destination Color * (1 - Source Alpha)).
31. Stride: The byte offset between consecutive generic vertex attributes in a VBO (e.g., the distance in memory from the start of vertex 1's position to vertex 2's position).
32. Geometry Shader: Unlike a Vertex shader which processes one vertex to one vertex, a Geometry shader can generate entirely new geometry (new vertices/primitives) on the fly.
33. Barycentric Coordinates: A coordinate system used to interpolate values (like color, normals, UVs) across the surface of a triangle based on the fragment's distance to the three vertices.
34. Draw Calls: glDrawArrays reads vertices sequentially from the VBO. glDrawElements uses an attached EBO to look up vertices by their index.
35. Gimbal Lock: The loss of one degree of freedom when rotating using Euler angles. It is prevented by using Quaternions, a 4D number system for representing rotations.
36. Normal Matrix: The inverse transpose of the upper-left 3x3 model-view matrix. It ensures surface normals remain perpendicular to the surface when non-uniform scaling is applied to the object.
37. GLEW/GLAD: Extension loaders. Because OpenGL function locations are not known at compile time, these libraries query the graphics driver at runtime to get the function pointers.
38. glViewport: Specifies the affine transformation that maps Normalized Device Coordinates (NDC) to window/screen coordinates (pixels).
39. Shading: Flat shading uses a single normal per polygon, making geometry look faceted. Smooth shading interpolates normals across the polygon, calculating lighting per-fragment for a curved look.
40. Identity Matrix: A matrix consisting of 1s on the main diagonal and 0s everywhere else. Multiplying any vector/matrix by it leaves the original vector/matrix unchanged.
41. Depth Buffer: It stores a depth value (Z) for every pixel on screen. Before drawing a fragment, the GPU checks if the fragment's Z is closer than the stored Z; if not, it is discarded.
42. Post-Processing: Rendering the entire 3D scene to an off-screen texture (FBO), and then rendering a flat 2D quad to the screen while applying a shader effect (like bloom or blur) to that texture.
43. Anti-Aliasing: Techniques used to smooth out the jagged, staircase-like edges of rasterized primitives caused by rendering geometric shapes onto a grid of square pixels.
44. texture() function: It samples a texel (color) from a bound texture in GLSL, using the provided 2D texture coordinates (UVs) and applying the configured filtering parameters.
45. Lighting: Ambient is a constant base light that affects all surfaces equally. Diffuse brightness depends directly on the angle between the surface normal and the incoming light ray.
46. 4x4 Matrices: A 3x3 matrix can only handle rotation and scaling. To apply Translation (movement) via multiplication, a 4th dimension (Homogeneous Coordinates) is required.
47. Draw Call: A command sent from the CPU to the GPU instructing it to render a set of primitives. High draw call counts cause CPU bottlenecks due to driver overhead.
48. Coordinate Spaces: Local space is relative to an object's own origin point. World space represents the position of the object relative to the absolute center (0,0,0) of the entire scene.
49. Bottlenecks: CPU bound means the processor cannot feed instructions (draw calls, logic) to the GPU fast enough. GPU bound means the GPU is struggling to process the heavy fragment/vertex math fast enough.
50. Sprite: A 2D bitmap image or animation integrated into a larger scene, historically processed via dedicated hardware but now rendered as textured 2D quads.
